Кейс 7. «Альфа Защита»
Разработать концепцию проекта и прототип системы под рабочим названием «Альфа Защита», которая используя комплекс технологий (AI, Big Data, Alfa ID и открытые API), сможет в режиме, близком к реальному времени, предотвращать финансовые мошенничества с переводом средств. 
Ключевые цели системы:
1.  Идентификация мошеннического инцидента на ранней стадии (звонок, смс, начало диалога в мессенджере).
2.  Проактивное предупреждение пользователя понятным и невозможным для игнорирования способом.
3.  Автоматизация реакции - возможность заблокировать подозрительную операцию или фейковый ресурс.
4.  Повышение финансовой грамотности населения через информирование.
3. Технологический стек для решения
 Командам предлагается интегрировать в свое решение следующие технологии:
 1. Искусственный интеллект (AI): NLP (Обработка естественного языка): Для анализа текстов смс-сообщений, чатов в мессенджерах и скриптов телефонных разговоров (после преобразования речи в текст). Должен определять психологическое давление, срочность, маркеры классических схем («блокировка счета», «помощь родственнику», «выигрыш в лотерею»).
 2. Computer Vision (Компьютерное зрение): Для идентификации фейковых интернет-страниц (фишинговых сайтов), имитирующих сайты банков или госуслуг, по скриншотам или через анализ URL.
 3. Поведенческий анализ: Для построения профиля пользователя и выявления аномалий в его действиях (например, человек, который никогда не переводил деньги незнакомцам, вдруг пытается сделать крупный перевод на новый для себя счет).
4. Big Data (Большие данные):
 Анализ больших массивов данных о транзакциях, номерах телефонов, IP-адресах, доменах для выявления сетевых мошеннических схем.
 5. Создание и постоянное обновление реестра цифровых угроз (черные списки номеров, кошельков, сайтов, шаблонов мошеннических сообщений).
6. Alfa ID: Использование этой технологии для надежной идентификации абонентов мобильной связи. Задача: отличить настоящий звонок из банка от звонка мошенника, который подделал номер (спуфинг). Например, интеграция с системой, где легитимный звонок от банка сопровождается верификацией через Alfa ID в мобильном приложении.
7. Открытые API: API банков и финансовых организаций (в рамках инициативы Open API): для безопасной проверки статуса операций, получения (с согласия пользователя) данных о поведенческих паттернах.
8. API МВД/Роскомнадзора:** для получения актуальных данных о заблокированных ресурсах и номерах, используемых мошенниками.
9. API мобильных операторов:** для интеграции системы оповещения.
Данный кейс для больший эвентов, с наличием времени у команд на  предварительную подготовку
Дополнение:
— бизнес-контекст:
Текущая проблема: мошенники всё чаще используют социальную инженерию, обходя традиционные системы защиты (2FA, лимиты). Пользователь сам инициирует перевод, и банк не может его остановить без нарушения UX.
Гипотеза: если внедрить ИИ, способный анализировать внешние коммуникации и поведение, можно снизить количество успешных атак на 30–50%, повысить доверие к банку и снизить расходы на возмещение убытков.
Дополнительная ценность:
Увеличение NPS за счёт ощущения «персональной защиты».
Снижение нагрузки на службу поддержки (меньше обращений по утерянным средствам).
Укрепление позиционирования Альфа-Банка как технологичного и безопасного банка.
— Ожидание от финального результата:
Интерактивный прототип (Figma или web), демонстрирующий:
получение подозрительного SMS,
анализ текста и контекста,
проактивное предупреждение,
блокировку перевода с объяснением.
10–15 сценариев обнаружения мошенничества, включая:
фишинговые SMS о блокировке карты,
звонки от «службы безопасности»,
переходы по фальшивым ссылкам,
попытки перевода после контакта с подозрительным номером.
ИИ-ассистент (мок), который:
классифицирует сообщения,
оценивает риск,
даёт рекомендации: «Не переходите по этой ссылке», «Позвоните в банк по официальному номеру».
UX-метрики по итогам тестирования:
доля пользователей, изменивших поведение после предупреждения,
время реакции на угрозу,
субъективная оценка полезности (по шкале от 1 до 5).
Презентация с исследованием, сценариями, результатами тестов и рекомендациями по внедрению.
— Необходимые компетенции:
Обязательные:
Понимание UX/UI и поведенческого дизайна.
Работа с Figma (создание интерактивных прототипов).
Базовые навыки анализа данных и построения user flows.
Желательно:
Опыт в NLP или машинном обучении (для мок-модели).
Frontend (React) — для живого прототипа.
Навыки проведения интервью и юзабилити-тестов.
