**Окончательные пользовательские сценарии — «Альфа Защита»**

Харченко Богдан Никитич, 11И2. Редакция от 21.09.2026.

Сценарии описывают итоговый продукт. Текущая реализация описана в
[first_code.md](first_code.md). Каждому [функциональному требованию](final_application.md)
соответствует сценарий с тем же номером: ФТ-01–ФТ-10 и ПС-01–ПС-10.

Во всех примерах используются синтетические данные и демонстрационные переводы.
Кроме регистрации и входа, сценарии выполняет авторизованный пользователь.
Десять пользовательских сценариев описывают взаимодействие с приложением;
15 демонстрационных ситуаций — подготовленные примеры для проверки его работы.

**ПС-01. Пользователь регистрируется и получает доступ к своим результатам — ФТ-01**

Цель: создать аккаунт и получить доступ к сохранённым результатам с другого устройства.

1. Пользователь открывает страницу входа и выбирает регистрацию.
2. Система показывает поля логина и пароля и требования к их заполнению.
3. Пользователь вводит логин, пароль и подтверждение пароля.
4. Система проверяет данные, создаёт аккаунт и открывает рабочую область пользователя.
5. Пользователь выполняет проверку сообщения по сценарию ПС-02.
6. Система сохраняет результат проверки в истории этого аккаунта.
7. Пользователь выходит из аккаунта и входит с теми же данными на другом поддерживаемом устройстве.
8. Система показывает ранее сохранённые результаты пользователя.

Альтернативы: При занятом логине или некорректном заполнении система предлагает исправить
данные. Неверный пароль не позволяет войти. После выхода просмотр защищённых страниц
требует повторного входа. Результаты другого пользователя недоступны.

**ПС-02. Пользователь проверяет подозрительное сообщение — ФТ-02**

Цель: оценить признаки мошенничества в тексте и получить понятные рекомендации.

1. Пользователь открывает форму проверки сообщения.
2. Система предлагает выбрать источник: SMS, сообщение мессенджера или текстовую расшифровку звонка.
3. Пользователь выбирает источник и вводит подготовленный текст.
4. Пользователь запускает проверку.
5. Система проверяет допустимость ввода и анализирует текст классификатором и правилами.
6. Система показывает оценку риска и признаки, повлиявшие на результат.
7. Система показывает ограничения анализа и рекомендации, а при высоком риске — заметное предупреждение.
8. Пользователь знакомится с результатом и при необходимости открывает предложенный учебный материал.

Альтернативы: Пустой или слишком длинный текст не принимается. При недоступности части
анализа система сообщает о неполном результате; при невозможности проверки — об ошибке.
Отсутствие обнаруженных признаков не обозначается как гарантия безопасности.

**ПС-03. Пользователь проверяет подозрительную ссылку — ФТ-03**

Цель: проверить признаки риска в адресе и наличие записи в демонстрационном реестре угроз.

1. Пользователь открывает форму проверки ссылки.
2. Система показывает поле URL и краткое описание возможностей проверки.
3. Пользователь вводит подготовленный адрес.
4. Пользователь запускает проверку.
5. Система проверяет формат адреса и выделяет его домен.
6. Система анализирует признаки адреса и проверяет совпадения с демонстрационным реестром угроз.
7. Система показывает результат, причины предупреждения и ограничения использованных данных.
8. Пользователь знакомится с рекомендациями и при необходимости открывает соответствующую учебную карточку.

Альтернативы: Некорректный адрес требует исправления. При недоступном или устаревшем
реестре система явно указывает ограничение. Отсутствие адреса в реестре не означает, что
он безопасен. Подозрительная ссылка отображается без автоматического перехода.

**ПС-04. Пользователь выбирает демонстрационный финансовый профиль — ФТ-04**

Цель: выбрать историю операций, относительно которой будет оцениваться новый перевод.

1. Пользователь открывает список демонстрационных финансовых профилей.
2. Система показывает подготовленные профили с краткими описаниями.
3. Пользователь выбирает профиль.
4. Система показывает его синтетическую историю операций: даты, суммы и условных получателей.
5. Пользователь открывает подробности одной из операций.
6. Система показывает сведения об операции и обозначает демонстрационный характер данных.
7. Пользователь выбирает использование этого профиля для последующих проверок.
8. Система сохраняет выбор и показывает активный профиль в форме нового перевода.

Альтернативы: Если истории недостаточно, система сообщает об этом. Смена профиля требует
новой оценки ранее подготовленного перевода. Выбор демонстрационного профиля не открывает
доступ к данным чужого аккаунта.

**ПС-05. Пользователь проверяет предполагаемый перевод — ФТ-05**

Цель: оценить необычность операции и учесть связанное подозрительное сообщение.

1. Пользователь открывает форму демонстрационного перевода.
2. Система показывает выбранный профиль и поля суммы и получателя.
3. Пользователь вводит сумму в рублях и условного получателя.
4. Пользователь выбирает связанную проверку подозрительного контакта из своей истории либо указывает отсутствие такого контакта.
5. Пользователь запускает оценку операции.
6. Система проверяет введённые данные и анализирует сумму, новизну получателя и доступный контекст относительно выбранной истории.
7. Система показывает оценку риска, обнаруженные признаки и недостаточность данных, если она есть.
8. Система предлагает допустимые дальнейшие действия: подтверждение, дополнительное подтверждение или отмену — в зависимости от решения.

Альтернативы: Неположительная сумма и недоступная пользователю связанная проверка
отклоняются. Недостаток истории не трактуется как безопасность. Изменение суммы,
получателя, профиля или связанного контекста требует повторной оценки.

**ПС-06. Пользователь подтверждает или отменяет демонстрационный перевод — ФТ-06**

Цель: выполнить разрешённое действие и получить достоверный статус операции.

1. Пользователь открывает результат проверки подготовленного перевода.
2. Система показывает решение и причины разрешения или ограничения операции.
3. Система показывает доступные действия и предупреждение, если оно требуется.
4. Пользователь выбирает подтверждение, когда оно разрешено, либо отмену.
5. Система проверяет принадлежность операции пользователю и актуальность её оценки.
6. Система выполняет разрешённый перевод в локальном симуляторе либо сохраняет отмену.
7. Система показывает итоговый статус с явным указанием, что операция демонстрационная.
8. Пользователь открывает сохранённую запись операции и видит результат своего действия.

Альтернативы: Запрещённую операцию нельзя выполнить, просто закрыв предупреждение или
отправив прямой запрос. Неактуальная оценка требует новой проверки. Повторное нажатие не
создаёт второй перевод. При ошибке система не показывает неподтверждённый успех.

**ПС-07. Пользователь просматривает историю и повторяет проверку — ФТ-07**

Цель: вернуться к прошлому результату и получить новую оценку, сохранив предыдущую.

1. Пользователь открывает историю своих проверок.
2. Система показывает записи с датой, типом проверки и последним результатом.
3. Пользователь выбирает нужную запись.
4. Система показывает проверенные данные, связанные оценки и выполненные действия.
5. Пользователь открывает одну из предыдущих оценок.
6. Система показывает её результат, основания и ограничения.
7. Пользователь запускает повторную проверку.
8. Система сохраняет новую оценку отдельной записью и показывает её, сохраняя доступ к предыдущим результатам.

Альтернативы: При пустой истории система предлагает выполнить первую проверку. Недоступные
пользователю записи не раскрываются. Ошибка повторного анализа не удаляет предыдущую
оценку и не делает её автоматически актуальной.

**ПС-08. Пользователь изучает материалы о мошенничестве — ФТ-08**

Цель: узнать признаки распространённой схемы и возможные безопасные действия.

1. Пользователь открывает каталог учебных материалов.
2. Система показывает карточки с названиями и краткими описаниями.
3. Пользователь выбирает интересующую тему.
4. Система показывает описание схемы, характерные признаки и рекомендуемые действия.
5. Пользователь открывает ранее сохранённый результат проверки.
6. Система показывает ссылки на материалы, связанные с обнаруженными признаками.
7. Пользователь выбирает рекомендованную карточку.
8. Система открывает материал с возможностью вернуться к результату проверки.

Альтернативы: Если специализированного материала нет, система предлагает общий материал и
обозначает замену. При ошибке загрузки система сообщает о недоступности карточки. Контакты
из подозрительного сообщения не используются как проверенные контакты помощи.

**ПС-09. Пользователь проходит подготовленную демонстрационную ситуацию — ФТ-09**

Цель: проверить работу приложения на готовом примере без самостоятельной подготовки данных.

1. Пользователь открывает каталог демонстрационных ситуаций.
2. Система показывает 15 подготовленных ситуаций с краткими описаниями.
3. Пользователь выбирает ситуацию.
4. Система создаёт отдельный запуск и подставляет соответствующие синтетические данные в формы приложения.
5. Пользователь выполняет проверки и выбирает действия через обычные экраны приложения.
6. Система рассчитывает результаты по введённым данным и сохраняет выполненные действия.
7. Пользователь выбирает начало нового запуска.
8. Система создаёт независимый запуск, сохраняя историю предыдущего для его владельца.

Альтернативы: Повреждённый пример не запускается; система объясняет ошибку. Обновление
страницы позволяет продолжить текущий запуск. Начало нового запуска не удаляет аккаунт и
предыдущую историю.

**ПС-10. Пользователь экспортирует результат проверки — ФТ-10**

Цель: сохранить выбранный результат отдельным файлом.

1. Пользователь открывает сохранённый результат проверки.
2. Система показывает команду скачивания JSON и краткое описание содержимого файла.
3. Пользователь выбирает скачивание.
4. Система проверяет доступ пользователя к выбранному результату.
5. Система формирует файл с типом проверки, временем, оценкой, причинами, рекомендациями и версиями анализа.
6. Система передаёт файл браузеру.
7. Пользователь сохраняет файл средствами браузера.
8. Пользователь открывает файл текстовым редактором и просматривает экспортированный результат.

Альтернативы: Чужие результаты недоступны для скачивания. При ошибке система предлагает
повторить запрос. В файл не включаются пароли, токены сессии и исходный текст сообщения.
