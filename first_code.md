**Что сделано**

Подготовлена техническая основа веб-приложения: серверная часть на Python/FastAPI,
база SQLite и начальный интерфейс на TypeScript/React. Код разделён на предметную
логику, прикладные сценарии, работу с хранилищем и HTTP API. Это позволяет отдельно
проверять правила анализа и подключать к ним интерфейс.

Реализованы следующие части проекта:

1. Хранение данных в SQLite, миграции и атомарное выполнение изменений. Есть защита
   от повторного выполнения одинаковой команды и журнал технических действий.
2. Демонстрационная сессия и управление согласиями. Начальный веб-интерфейс создаёт
   сессию через сервер и восстанавливает её после обновления страницы.
3. Загрузка синтетических примеров и проверка их формата, версий и целостности.
4. Демонстрационный реестр угроз. Проверка различает совпадение с известной записью,
   отсутствие совпадения и недоступность данных реестра.
5. Внутренний приём текстов SMS, сообщений, расшифровок звонков и адресов ресурсов.
   Исходный текст сохраняется отдельно от нормализованных признаков.
6. Объединение связанных наблюдений в предварительные инциденты в пределах одной
   рабочей области. Новые сведения меняют версию контекста для последующего анализа.
7. Анализ текста и URL по правилам: оценка риска, основания результата и указание
   полноты проверки. Эта часть пока вызывается внутри серверного кода.
8. Подбор русскоязычных рекомендаций по результату анализа и каталог из семи
   учебных карточек. Список и содержимое карточек доступны через API активной
   демонстрационной сессии.

**Что можно проверить сейчас**

После запуска по инструкции можно открыть начальный веб-интерфейс, создать
демонстрационную сессию, изменить согласия и обновить страницу с сохранением сессии.
Через API доступны проверка состояния сервера и каталог учебных карточек.
Приём наблюдений, объединение инцидентов и оценка риска проверяются тестами;
полный пользовательский путь проверки сообщения ещё не подключён к интерфейсу.

В [журнале приёмки P12](docs/IMPLEMENTATION_PLAN.md#log-2026-09-21-p12-01)
за 21.09.2026 зафиксированы 183 успешных backend-теста и 9 frontend-тестов,
проверки типов, линтеры и сборка. Это результаты проверки версии кода `2ca3ca8`;
подготовка этого описания не является новым запуском тестов.

**Что ещё предстоит сделать**

Завершены технические этапы P01–P12. Полностью реализованных сквозных сценариев
ПС-01–ПС-10 пока нет. Нужны обычные аккаунты с логином и паролем, собственный
текстовый датасет и обученный классификатор, экраны проверок и предупреждений,
финансовые профили и симулятор переводов, история, экспорт и каталог из 15 ситуаций.
После этого предстоят пользовательское исследование и подготовка защиты.

Текущий анализ работает по правилам. Демонстрационная сессия не заменяет обычную
регистрацию. Реальные банковские операции и внешние банковские сервисы не подключены.
